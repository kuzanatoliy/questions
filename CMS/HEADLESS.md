# Headless CMS

<details>
  <summary>What headless CMS?</summary>

A headless CMS is a back-end web content management system that stores and manages content without a built-in front-end presentation layer

</details>

<details>
  <summary>What is pros and cons compared to a traditional CMS?</summary>

Pros:

- Omnichannel Delivery: Publishes content to websites, mobile apps, smart devices, Lot, and AI agents using the same data source
- Flexibility & Freedom: Developers can use modern JavaScritp frameworks instead of being locked into old template languates
- Better Performance & Scalability: Separating rendering from the database allows front-end apps to load faster and scale independently in the cloud.
- Stronger Security: Public-facing sites only have read-only API access, shrinking teh security attack sufrace

Cons:

- Higher Upfront Const & Complexity: Requires technical expertiese to set up, model structured content, and build custom front-ends.
- No Native Preview / MYSIWYG: Content editors lack out-of-the-box "what-you-see-is what-you-get" page builders;
- Fragmented Tooling: Teams often have to pieces together separate services for hosting, search and from handling.

</details>

<details>
  <summary>What are SAAS and CASS?</summary>

SAAS (Software as a Service) - It is ready Software, that is possible to use. In the case provider takes responsibilities for servers, DB, Code base, updates and security. Examples: Microsoft 365, Google Workspace

CAAS (Container as a service) - It is model that allows to deploy sofware in containers (For example: docker, kubernetes). In the case provider manage Hardware and container orcestration. Code and settins is customer responsibility. Examples: Google Kubernetes Engine

</details>
